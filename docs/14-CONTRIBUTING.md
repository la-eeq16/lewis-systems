# Documentation Contribution Standards

- Maintain one authoritative location for each current specification.
- Use relative links between repository documents.
- Mark historical documents as legacy and link to the current source.
- Distinguish implemented, recorded, verified, planned, and blocked work.
- Include evidence for successful testing claims.
- Update the Project Index and Project Status after structural or milestone changes.
- Never include credentials, customer personal information, or unredacted connection metadata.
- Do not populate placeholders with invented implementation details.

See the root [CONTRIBUTING.md](../CONTRIBUTING.md) and [Security Standards](16-SECURITY.md).
